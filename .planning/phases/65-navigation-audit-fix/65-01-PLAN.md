# Phase 65-01: Navigation Audit & Fix

## Objective

Fix sidebar job selection pattern across all pages so job selection always uses the sidebar with URL state persistence.

## Requirements

- NAV-01: Staff can see which pages have job selection in main window vs sidebar
- NAV-02: All pages use sidebar job selection pattern (never in main window)
- NAV-03: Job selection persists in URL (`?job=uuid`) across page refreshes

## Tasks

### Task 1: Audit all pages for navigation patterns
- [x] Identify all HTML pages in public/
- [x] Check each page for job selection implementation
- [x] Document which pages have broken navigation

**Findings:**
- 37 pages correctly use sidebar.js
- 3 pages have broken navigation:
  - job-hub.html/js - Custom job selector in main content
  - budget-builder.html/js - Custom job selector in header
  - permits.html/js - Has jobFilter in toolbar (redundant with sidebar)

### Task 2: Add URL state persistence to sidebar.js
- [x] Add URL parameter handling (`?job=uuid`)
- [x] Read job from URL on init (priority over localStorage)
- [x] Update URL when job selection changes
- [x] Handle browser back/forward (popstate event)

### Task 3: Fix Job Hub page
- [x] Remove custom job selector from HTML
- [x] Update JS to use JobSidebar.onJobChange()
- [x] Remove duplicate URL handling code

### Task 4: Fix Budget Builder page
- [x] Remove custom job selector from HTML
- [x] Update JS to use JobSidebar.onJobChange()
- [x] Remove duplicate URL handling code

### Task 5: Fix Permits page
- [x] Remove jobFilter from toolbar HTML
- [x] Update JS to use JobSidebar.onJobChange() for filtering
- [x] Remove jobFilter event listener

## Verification

- [x] All pages load without errors
- [x] Job selection in sidebar updates URL
- [x] Page refresh preserves job selection
- [x] Job Hub, Budget Builder, Permits all use sidebar for job selection
