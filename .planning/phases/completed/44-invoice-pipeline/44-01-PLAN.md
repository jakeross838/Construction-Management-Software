<objective>
Add allocation cleanup logic when invoice status transitions to denied or when invoice is deleted.

Purpose: INV-INT-01 - Ensure PO line items and CO amounts are correctly reversed when an invoice is denied or deleted, preventing orphaned allocation data from corrupting budget tracking.

Output: cleanupInvoiceAllocations helper function that removes allocations and updates related PO/CO amounts.
</objective>

<task type="auto">
  <name>Task 1: Create cleanupInvoiceAllocations helper function</name>
  <files>server/services/invoiceHelpers.js</files>
  <action>
Add a new function `cleanupInvoiceAllocations(invoiceId)` that:

1. Fetches all allocations for the invoice from v2_invoice_allocations including po_id, po_line_item_id, change_order_id, cost_code_id, amount
2. For each allocation with a po_id:
   - Call `updatePOLineItemsForAllocations(po_id, [allocation], false)` to decrement invoiced_amount
3. For each allocation with a change_order_id:
   - Fetch current invoiced_amount from v2_job_change_orders
   - Decrement by allocation amount (Math.max(0, current - allocation.amount))
   - Update v2_job_change_orders.invoiced_amount
4. Delete all allocations from v2_invoice_allocations where invoice_id matches
5. Return { success: true, allocations_removed: count }

Export the function in module.exports.

The function should be safe to call even if there are no allocations (no-op).
  </action>
  <verify>Function exists and is exported from invoiceHelpers.js</verify>
  <done>cleanupInvoiceAllocations function handles PO line item decrement, CO invoiced_amount decrement, and allocation deletion</done>
</task>
