Create migration file that adds template task storage:

1. Create v2_schedule_template_tasks table:
```sql
CREATE TABLE v2_schedule_template_tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id UUID NOT NULL REFERENCES v2_schedule_templates(id) ON DELETE CASCADE,

  -- Task identity (copied from source task)
  name TEXT NOT NULL,
  description TEXT,
  phase TEXT,
  trade_id TEXT,  -- Store as text for template portability

  -- Relative timing (calculated from source)
  relative_start_day INTEGER NOT NULL DEFAULT 0,  -- Day 0 = project start
  relative_end_day INTEGER NOT NULL DEFAULT 0,
  duration_days INTEGER NOT NULL DEFAULT 1,

  -- Template-specific
  sort_order INTEGER DEFAULT 0,
  notes TEXT,

  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

2. Create v2_schedule_template_dependencies table:
```sql
CREATE TABLE v2_schedule_template_dependencies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id UUID NOT NULL REFERENCES v2_schedule_templates(id) ON DELETE CASCADE,

  -- Reference by sort_order since task IDs won't exist yet
  predecessor_sort_order INTEGER NOT NULL,
  successor_sort_order INTEGER NOT NULL,

  dependency_type TEXT DEFAULT 'FS',
  lag_days INTEGER DEFAULT 0,

  UNIQUE(template_id, predecessor_sort_order, successor_sort_order)
);
```

3. Add source_schedule_id to v2_schedule_templates for tracking

4. Create indexes on template_id columns

<task type="auto">
  <name>Task 2: Add template management endpoints</name>
  <files>server/routes/schedules.js</files>
  <action>
Add template endpoints to schedules.js (near existing /templates GET):

1. POST /templates/from-schedule
   - Request: { source_schedule_id, name, description, project_type }
   - Logic:
     a. Get source schedule with tasks and dependencies
     b. Find earliest task start date as anchor (Day 0)
     c. For each task:
        - relative_start_day = daysDiff(anchor, task.planned_start)
        - relative_end_day = daysDiff(anchor, task.planned_end)
        - duration_days = relative_end_day - relative_start_day + 1
     d. Insert template record
     e. Insert template_tasks with relative days
     f. Copy dependencies using sort_order mapping
   - Returns: { template_id, task_count }

2. POST /templates/:templateId/apply
   - Request: { job_id, start_date, created_by }
   - Logic:
     a. Check if job already has schedule (return 409 if exists)
     b. Create new schedule for job with start_date
     c. For each template_task:
        - planned_start = start_date + relative_start_day
        - planned_end = start_date + relative_end_day
        - Create task with absolute dates
     d. Map old sort_orders to new task IDs
     e. Create dependencies using the mapping
     f. Call recalculate_schedule RPC
   - Returns: { schedule_id, tasks_created }

3. GET /templates/:templateId (with tasks)
   - Include template_tasks in response
   - Show preview of what would be created

4. DELETE /templates/:templateId
   - Cascade deletes template_tasks and template_dependencies
  </action>
  <verify>POST /api/schedules/templates/from-schedule creates template with relative days</verify>
  <done>Templates can be saved from schedules and applied to new jobs</done>
