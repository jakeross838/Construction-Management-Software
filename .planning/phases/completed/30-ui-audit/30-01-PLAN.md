  <name>Task 1: Create UI Standards Document</name>
  <files>.planning/UI-STANDARDS.md</files>
  <action>
Create a comprehensive UI standards reference document based on the audit findings. The document should define THE standard pattern for each component type:

## Structure:
1. **CSS Variables** - Document all variables from :root with their purposes
2. **Buttons** - Standard classes: `btn`, `btn-primary`, `btn-secondary`, `btn-danger`, `btn-ghost`, `btn-sm`, `btn-lg`, `btn-icon`
3. **Badges/Status** - Standardize on `status-badge` with modifiers. Document the status color mappings.
4. **Cards** - Standardize on `.card` base class with variants: `.card-stat`, `.card-summary`, `.card-alert`
5. **Tables** - Standardize on `.data-table` as base with modifiers: `.data-table-hover`, `.data-table-selectable`
6. **Modals** - Standard structure with `.modal`, `.modal-content`, `.modal-header`, `.modal-body`, `.modal-footer`. Sizes: `.modal-sm`, `.modal-md`, `.modal-lg`, `.modal-fullscreen`
7. **Forms** - Standard classes: `.form-group`, `.form-row`, `.form-control`, `.form-control-sm`
8. **Toolbars** - Standardize on `.toolbar` with `.toolbar-left`, `.toolbar-right`
9. **Search** - Standard `.search-box` pattern
10. **Loading States** - Standard `.skeleton`, `.spinner` patterns

For each component, include:
- Correct HTML structure
- Required CSS classes
- Variants and when to use them
- Anti-patterns to avoid

Use the existing CSS variables from styles.css - don't invent new ones.
