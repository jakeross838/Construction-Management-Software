<task type="auto">
  <name>Task 1: Create budget accuracy endpoint</name>
  <files>server/routes/jobs.js</files>
  <action>
Add GET /api/jobs/:jobId/budget-accuracy endpoint that:

1. Fetches all budget lines for the job with cost code details
2. For each cost code, calculate:
   - budgeted_amount (original budget)
   - committed_amount (POs + COs approved)
   - billed_amount (invoices in draws)
   - paid_amount (payments recorded)
   - remaining_to_commit: budgeted - committed
   - remaining_to_bill: committed - billed
   - variance_committed: committed - budgeted (negative = under, positive = over)
   - variance_billed: billed - budgeted

3. Aggregate into job-level summary:
   - total_budgeted
   - total_committed
   - total_billed
   - total_paid
   - overall_variance_committed
   - overall_variance_billed
   - percent_committed: (committed / budgeted) * 100
   - percent_billed: (billed / budgeted) * 100

4. Flag issues:
   - over_committed: cost codes where committed > budgeted (error)
   - over_billed: cost codes where billed > committed (error)
   - approaching_limit: cost codes where committed > 90% of budgeted (warning)

Return format:
```javascript
{
  job_id: string,
  job_name: string,
  valid: boolean,
  summary: {
    total_budgeted: number,
    total_committed: number,
    total_billed: number,
    total_paid: number,
    overall_variance: number,
    percent_committed: number,
    percent_billed: number,
    cost_codes_over_committed: number,
    cost_codes_approaching_limit: number
  },
  by_cost_code: [{
    cost_code_id: string,
    cost_code: string,
    cost_code_name: string,
    budgeted: number,
    committed: number,
    billed: number,
    paid: number,
    variance_committed: number,
    variance_billed: number,
    percent_committed: number,
    status: 'ok' | 'approaching' | 'over_committed' | 'over_billed'
  }],
  errors: [...],
  warnings: [...]
}
```

Place near existing budget endpoints.
  </action>
  <verify>curl http://localhost:3001/api/jobs/{jobId}/budget-accuracy returns variance report with by_cost_code breakdown</verify>
  <done>Budget accuracy endpoint returns comprehensive variance analysis by cost code</done>
</task>

<task type="auto">
  <name>Task 2: Add what-if analysis for pending COs</name>
  <files>server/routes/jobs.js</files>
  <action>
Enhance budget-accuracy endpoint with what-if analysis:

1. Query pending (non-approved) COs for the job
2. Sum their impact by cost code (from CO line items)
3. Add projection section showing budget state if pending COs approved:
   - projected_committed: committed + pending CO amounts
   - projected_variance: projected_committed - budgeted
   - would_be_over: list of cost codes that would exceed budget

4. Add to response:
```javascript
{
  // Existing fields...
  pending_changes: {
    pending_co_count: number,
    pending_co_total: number,
    pending_vpo_count: number,
    pending_vpo_total: number,
    by_cost_code: [{
      cost_code_id: string,
      cost_code: string,
      pending_amount: number,
      current_committed: number,
      projected_committed: number,
      budgeted: number,
      would_exceed_budget: boolean,
      projected_variance: number
    }]
  },
  what_if_approved: {
    projected_total_committed: number,
    projected_total_variance: number,
    cost_codes_would_exceed: number,
    warnings: [{
      type: 'WOULD_EXCEED_BUDGET',
      cost_code: string,
      budgeted: number,
      projected_committed: number,
      excess: number,
      message: 'Approving pending COs would exceed budget by $X for {cost_code}'
    }]
  }
}
```

This helps users understand the impact of approving pending COs before they commit.
