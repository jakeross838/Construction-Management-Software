Add baseline schedule support - the ability to capture a snapshot of the original planned schedule and compare it against current dates.

Purpose: Project managers need to track schedule slippage by comparing current dates against the original plan. This is Buildertrend's #1 high-value feature for schedule management.

Output: Database migration adding baseline fields, API endpoints to set/view baselines, baseline data available for frontend.
</objective>

  <name>Task 1: Create baseline migration</name>

Create migration file that adds baseline tracking fields:

1. Add columns to v2_schedule_tasks:
   - baseline_start DATE
   - baseline_end DATE

2. Add columns to v2_schedules:
   - baseline_set_at TIMESTAMPTZ
   - baseline_set_by TEXT

3. Create helper function copy_to_baseline(p_schedule_id UUID) that:
   - Copies planned_start -> baseline_start for all tasks
   - Copies planned_end -> baseline_end for all tasks
   - Sets baseline_set_at and baseline_set_by on schedule

4. Create index on baseline columns for performance

Follow existing migration naming pattern (migration-115-*).
Use ALTER TABLE ADD COLUMN IF NOT EXISTS for safety.

<task type="auto">
  <name>Task 2: Add baseline API endpoints</name>
  <files>server/routes/schedules.js</files>
  <action>
Add two endpoints to schedules.js:

1. POST /:id/set-baseline
   - Calls copy_to_baseline RPC
   - Requires confirmation if baseline already exists (check baseline_set_at)
   - Request body: { set_by: string, force?: boolean }
   - Returns: { success: true, baseline_set_at: timestamp }

2. GET /:id/baseline
   - Returns schedule with baseline data for comparison
   - For each task, calculate variance_days = daysDiff(planned_end, baseline_end)
   - Include baseline_set_at timestamp
   - Format response:
     ```json
     {
       schedule_id: "...",
       baseline_set_at: "2026-01-15T...",
       baseline_set_by: "Jake",
       tasks: [
         {
           id: "...",
           name: "Foundation",
           baseline_start: "2026-02-01",
           baseline_end: "2026-02-14",
           planned_start: "2026-02-03",
           planned_end: "2026-02-18",
           variance_days: 4  // positive = behind
         }
       ],
       summary: {
         total_tasks: 25,
         on_schedule: 18,
         behind_schedule: 5,
         ahead_schedule: 2,
         total_variance_days: 12
       }
     }
     ```

Add endpoints after existing schedule CRUD but before task endpoints.
Use asyncHandler pattern consistent with existing code.
  </action>
  <verify>curl -X POST http://localhost:3001/api/schedules/{id}/set-baseline returns success (after migration applied)</verify>
  <done>Baseline can be set via API and variance data returned</done>
</task>
