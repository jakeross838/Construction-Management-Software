<task type="auto">
  <name>Task 1: Create PO total validation endpoint</name>
  <files>server/routes/purchase-orders.js</files>
  <action>
Add GET /api/purchase-orders/:id/validate-totals endpoint that:

1. Fetches the PO with its stored totals (original_amount, change_order_total, total_amount)
2. Fetches all approved COs for this PO and sums their amount_change
3. Fetches all approved VPOs for this PO and sums their amounts
4. Compares:
   - change_order_total should equal sum of approved CO amount_changes
   - total_amount should equal original_amount + change_order_total
   - VPO total should be tracked (may not be in change_order_total currently)

5. Fetches budget lines linked to PO line items
6. Validates committed_amount on budget reflects CO additions:
   - Each approved CO line item should have incremented committed_amount

Return format:
```javascript
{
  valid: boolean,
  po_id: string,
  po_number: string,
  calculated: {
    original_amount: number,
    co_total: number,
    vpo_total: number,
    expected_total: number,
    committed_to_budget: number
  },
  stored: {
    original_amount: number,
    change_order_total: number,
    total_amount: number
  },
  errors: [{ type, severity, details, fix_hint }],
  warnings: [{ type, severity, details, fix_hint }]
}
```

Error types:
- CO_TOTAL_MISMATCH - change_order_total doesn't match sum of approved COs
- PO_TOTAL_MISMATCH - total_amount doesn't match original + COs
- CO_NOT_IN_BUDGET - approved CO line items not reflected in budget committed_amount
- VPO_NOT_TRACKED - VPOs exist but not in any total (warning)

Place near PO validation endpoints.
  </action>
  <verify>curl http://localhost:3001/api/purchase-orders/{poId}/validate-totals returns JSON with calculated vs stored comparison</verify>
  <done>Endpoint validates PO totals against actual CO/VPO data</done>
</task>

  <action>
Add GET /api/jobs/:jobId/validate-po-totals endpoint that:

1. Fetches all POs for the job (non-deleted, non-cancelled)
2. Runs validation for each PO
3. Aggregates results into job-level summary

Return format:
```javascript
{
  job_id: string,
  valid: boolean,
  summary: {
    pos_checked: number,
    pos_with_errors: number,
    pos_with_warnings: number,
    total_co_discrepancy: number,
    total_vpo_untracked: number
  },
  po_results: [
    {
      po_id: string,
      po_number: string,
      valid: boolean,
      error_count: number,
      warning_count: number,
      co_discrepancy: number
    }
  ],
  errors: [...],  // Aggregated from all POs
  warnings: [...]  // Aggregated from all POs
}
```

This allows checking all POs for a job in one call before generating a draw or finalizing job billing.
  </action>

  <done>Job-level PO validation returns summary and per-PO results</done>
