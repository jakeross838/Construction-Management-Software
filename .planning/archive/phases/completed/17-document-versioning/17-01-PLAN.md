# Plan 17-01: Document Version System

<objective>
Add version tracking, history viewing, and rollback capabilities to job documents. Users can upload new versions of existing documents, view version history with timestamps and uploaders, compare versions side-by-side, and rollback to any previous version.

Purpose: Complete DOC-03 requirement - proper document version management for construction project documentation.
Output: Database schema, API endpoints, and UI for document version management.
</objective>

## Context

**Existing state:**
- `v2_documents` table stores job documents (single version per record, soft delete via deleted_at)
- `v2_vendor_documents` uses `is_current` flag pattern for version tracking (proven pattern)
- Documents stored in Supabase Storage at `documents/{job_id}/{uuid}_{filename}`
- `v2_document_activity` already logs document actions (uploaded, viewed, downloaded, updated, deleted)
- Document detail modal in `public/js/documents.js` shows metadata and preview

**Gap:**
- `v2_documents` lacks version tracking (no version_number, no parent_id, no is_current flag)
- No API endpoint to upload new version of existing document
- No UI to view version history or compare versions
- No rollback functionality

**Approach:**
1. Add version columns to `v2_documents` (version_number, parent_document_id, is_current)
2. Create migration that initializes existing documents as version 1
3. Add API endpoints: upload new version, get version history, rollback
4. Add UI: version history tab in detail modal, version comparison view, rollback button

## Tasks

### Task 1: Add version tracking columns to v2_documents
**File:** `database/migration-049-document-versioning.sql`

```sql
-- Add version tracking to v2_documents
ALTER TABLE v2_documents
ADD COLUMN IF NOT EXISTS version_number INTEGER DEFAULT 1,
ADD COLUMN IF NOT EXISTS parent_document_id UUID REFERENCES v2_documents(id),
ADD COLUMN IF NOT EXISTS is_current BOOLEAN DEFAULT true;

-- Initialize existing documents as version 1, is_current=true
UPDATE v2_documents SET version_number = 1, is_current = true
WHERE version_number IS NULL;

-- Index for efficient version queries
CREATE INDEX IF NOT EXISTS idx_documents_parent_id ON v2_documents(parent_document_id);
CREATE INDEX IF NOT EXISTS idx_documents_is_current ON v2_documents(is_current) WHERE is_current = true;

-- Constraint: only one current version per parent chain
-- (handled in application logic due to complexity of the constraint)
```

### Task 2: Add version API endpoints
**File:** `server/routes/documents.js`

Add three new endpoints:

**POST /api/documents/:id/versions** - Upload new version of existing document
```javascript
// 1. Get current document and validate
// 2. Mark current as is_current = false
// 3. Upload new file to storage with new UUID
// 4. Insert new document record with:
//    - parent_document_id = original document id (or parent's parent_document_id if versioning a version)
//    - version_number = previous version + 1
//    - is_current = true
//    - Copy job_id, category, tags from original
// 5. Log activity: 'new_version' with version number
// 6. Return new document record
```

**GET /api/documents/:id/versions** - Get version history for a document
```javascript
// 1. Get the document
// 2. Find root parent (follow parent_document_id chain OR use current doc if no parent)
// 3. Query all documents where parent_document_id = root OR id = root
// 4. Order by version_number DESC
// 5. Return array with: id, version_number, file_url, file_name, file_size, uploaded_by, created_at, is_current
```

**POST /api/documents/:id/rollback** - Rollback to a previous version
```javascript
// 1. Get target version document
// 2. Find current version (is_current = true in same parent chain)
// 3. Mark current as is_current = false
// 4. Mark target as is_current = true
// 5. Log activity: 'rollback' with from/to version numbers

```
