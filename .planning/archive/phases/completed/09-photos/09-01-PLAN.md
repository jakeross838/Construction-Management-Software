<task type="auto">
  <name>Task 1: Create database migration for photos</name>
  <files>database/migration-045-photos.sql</files>
  <action>
Create migration file with:

1. **v2_photos** - Main photos table:
   ```sql
   id UUID PRIMARY KEY
   job_id UUID NOT NULL REFERENCES v2_jobs(id)
   file_url TEXT NOT NULL
   file_name TEXT
   thumbnail_url TEXT           -- For gallery grid performance
   caption TEXT
   location TEXT                -- Area/room within job site
   category TEXT DEFAULT 'progress' CHECK (progress, exterior, interior, detail, issue, completion)
   taken_at TIMESTAMPTZ         -- When photo was taken (from EXIF or manual)
   latitude DECIMAL(10,8)       -- GPS if available
   longitude DECIMAL(11,8)
   uploaded_by TEXT
   created_at TIMESTAMPTZ DEFAULT NOW()
   deleted_at TIMESTAMPTZ       -- Soft delete
   ```

2. **v2_photo_links** - Junction table for entity linking:
   ```sql
   id UUID PRIMARY KEY
   photo_id UUID NOT NULL REFERENCES v2_photos(id) ON DELETE CASCADE
   entity_type TEXT NOT NULL CHECK (inspection, punch_item, daily_log)
   entity_id UUID NOT NULL
   created_at TIMESTAMPTZ DEFAULT NOW()
   UNIQUE(photo_id, entity_type, entity_id)
   ```

3. **v2_photo_activity** - Audit trail:
   ```sql
   id UUID PRIMARY KEY
   photo_id UUID NOT NULL REFERENCES v2_photos(id) ON DELETE CASCADE
   action TEXT NOT NULL
   performed_by TEXT
   details JSONB
   created_at TIMESTAMPTZ DEFAULT NOW()
   ```

4. Indexes for performance:
   - idx_photos_job ON v2_photos(job_id) WHERE deleted_at IS NULL
   - idx_photos_category ON v2_photos(category) WHERE deleted_at IS NULL
   - idx_photos_taken ON v2_photos(taken_at DESC) WHERE deleted_at IS NULL
   - idx_photo_links_photo ON v2_photo_links(photo_id)
   - idx_photo_links_entity ON v2_photo_links(entity_type, entity_id)

Follow pattern from migration-038-punch-lists.sql for structure.
  </action>

<task type="auto">
  <name>Task 2: Create photos API routes</name>
  <files>server/routes/photos.js</files>
  <action>
Create Express router with multer for file uploads. Follow punch-lists.js pattern.

**Routes to implement:**

1. `GET /api/photos/stats` - Statistics by job
   - Query params: job_id (optional)
   - Returns: { total, by_category: {...}, by_month: {...} }

2. `GET /api/photos` - List photos with filters
   - Query params: job_id, category, search (caption), start_date, end_date, entity_type, entity_id, limit, offset
   - Returns: { data: [...], count }
   - Include entity links in response
   - Order by taken_at DESC (most recent first)

3. `GET /api/photos/:id` - Get single photo with links and activity
   - Include v2_photo_links with entity details
   - Include v2_photo_activity

4. `POST /api/photos` - Upload photo (multipart/form-data)
   - Accept: file (required), job_id (required), caption, location, category, taken_at, latitude, longitude, uploaded_by
   - Validate image types: jpeg, jpg, png, gif, webp
   - Storage path: `photos/{job_id}/{timestamp}_{filename}`
   - Use Supabase storage bucket 'invoices' (existing bucket)
   - Log activity: photo_uploaded
   - Return created photo record

5. `PATCH /api/photos/:id` - Update photo metadata
   - Can update: caption, location, category, taken_at
   - Log activity: photo_updated

6. `DELETE /api/photos/:id` - Soft delete
   - Set deleted_at timestamp
   - Log activity: photo_deleted

7. `POST /api/photos/:id/links` - Link photo to entity
   - Body: { entity_type, entity_id }
   - Validate entity_type is valid
   - Log activity: photo_linked

8. `DELETE /api/photos/:id/links/:linkId` - Remove entity link
   - Log activity: photo_unlinked

9. `GET /api/photos/by-entity/:entityType/:entityId` - Get photos for an entity
   - Returns all photos linked to specified entity

**Helper function:**
- `logPhotoActivity(photoId, action, performedBy, details)` - Activity logging

Use asyncHandler wrapper from ../errors for error handling.
Validate job exists before upload.
  </action>
