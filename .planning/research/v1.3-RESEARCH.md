## Executive Summary

This research covers best practices for the two v1.3 focus areas:
1. **Invoice AI Improvements** - Extraction accuracy, PO/job matching, approval workflow
2. **Reporting Suite** - Financial summaries, Excel exports, PDF reports

Key findings:
- Hybrid OCR + LLM architectures achieve 97%+ extraction accuracy
- Two-stage pipelines (extract → validate) improve reliability
- Schema enforcement and strict JSON validation are critical
- pdfmake excels for tabular reports; Puppeteer for complex layouts
- Construction financial reports follow established AIA G702/G703 patterns

## 1. Invoice AI Improvements

### 1.1 Current System Analysis

The existing system uses:
- **Claude Sonnet** for invoice data extraction
- **pdf-parse** for text extraction
- **OCR via Claude Vision** for scanned documents
- **AI Learning System** that records corrections (90% initial confidence, +2% per confirmation)
- **Confidence thresholds**: HIGH (0.90), MEDIUM (0.60), LOW (0.60)

**Existing schema** extracts: vendor info, invoice details, job references, amounts, line items, and self-reported extraction confidence.

### 1.2 Industry Best Practices

#### Two-Stage Pipeline Architecture
Research shows splitting extraction into two focused stages improves accuracy:

| Stage | Purpose |
|-------|---------|
| **Stage 1: Extraction** | Extract core fields into schema-perfect JSON |
| **Stage 2: Validation** | Apply business logic, cross-checking, enrichment |

*Source: [RaftLabs Invoice Scanning](https://www.raftlabs.com/blog/ocr-vs-llm-how-we-built-automated-invoice-scanning/)*

#### Schema Enforcement
- Define strict JSON schemas using Zod or similar validation
- Pair strong prompts with strict schema validation
- Current system uses inline schema in prompt — could benefit from programmatic validation

*Source: [arXiv Paper on LLM Invoice Extraction](https://arxiv.org/abs/2511.05547)*

#### Native Image Processing
Multi-modal LLMs with native image processing consistently outperform text-only approaches:
- Visual context and layout understanding are crucial
- Claude Sonnet 3.5 shows highest accuracy across document quality spectrum

*Source: [AI Multiple Invoice OCR Benchmark](https://research.aimultiple.com/invoice-ocr/)*

#### Image Pre-processing
Techniques that improve extraction:
- Median filtering and gaussian blur for image enhancement
- Rotation and skew compensation for misaligned documents
- Automatic detection of multi-page invoices

### 1.3 Recommended Improvements

#### A. Extraction Accuracy

| Current | Improvement |
|---------|-------------|
| Single-pass extraction | Two-stage: extract → validate |
| Inline confidence | Programmatic confidence scoring with tiered thresholds |
| Text-only for digital PDFs | Always use vision mode for layout context |

**Confidence Scoring Architecture:**
```javascript
// Tiered decision thresholds
const THRESHOLDS = {
  AUTO_APPROVE: 0.95,    // High confidence → auto-accept
  HUMAN_REVIEW: 0.80,    // Medium → route to review queue
  REJECT: 0.70           // Low → flag for investigation
};

// Stage 1: Raw extraction with Claude vision
const extracted = await claudeExtract(pdfImage, EXTRACTION_SCHEMA);

// Stage 2: Validation + enrichment
const validated = await validateAndEnrich(extracted, {
  jobs: existingJobs,
  vendors: existingVendors,
  poNumbers: existingPOs
});

// Stage 3: Cross-field validation
validateAmounts(validated);  // Line items sum = total
validateDates(validated);    // Invoice date reasonable
validateVendor(validated);   // Vendor exists in registry

// Route based on confidence
if (validated.confidence >= THRESHOLDS.AUTO_APPROVE) {
  await autoApprove(validated);
} else if (validated.confidence >= THRESHOLDS.REJECT) {
  await routeToReview(validated);
} else {
  await flagForInvestigation(validated);
}
```

**Expected Results:**
- 95-98% accuracy on well-structured invoices
- 75-85% Straight-Through Processing (STP) rate
- 15-25% routed to human review (acceptable for high overall accuracy)

#### B. PO/Job Matching

**Algorithm Selection:**

| Algorithm | Use Case | Threshold |
|-----------|----------|-----------|
| **Jaro-Winkler** | Vendor names, short strings | 0.85+ |
| **Trigrams (pg_trgm)** | Multi-word descriptions | 0.75+ |
| **Exact match** | PO numbers, invoice numbers | 1.0 |

**Multi-Signal Weighted Scoring:**
```javascript
function calculateMatchScore(invoice, candidate) {
  const signals = [
    { weight: 0.40, score: vendorSimilarity(invoice.vendor, candidate.vendor) },
    { weight: 0.25, score: poNumberMatch(invoice.poRef, candidate.poNumber) },
    { weight: 0.15, score: amountProximity(invoice.amount, candidate.remaining, 0.10) },
    { weight: 0.10, score: dateRelevance(invoice.date, candidate.poDate, 90) },
    { weight: 0.10, score: lineItemMatch(invoice.items, candidate.items) }
  ];
  return signals.reduce((sum, s) => sum + s.weight * s.score, 0);
}

// Decision logic
if (matchScore >= 0.95) autoMatch();
else if (matchScore >= 0.80) reviewQueue();
else flagForInvestigation();
```

**Handling Missing PO Reference:**
1. Match vendor first (fuzzy 0.85+ threshold)
2. Check amount range against recent POs from that vendor (±10%)
3. Verify date proximity (invoice date within 30 days of PO)
4. If multiple candidates remain, flag for manual review with scoring explanation

**Database Query Pattern:**
```sql
-- Pre-filter candidates (blocking query)
SELECT inv.*, pos.id as po_id,
  similarity(inv.vendor_name, pos.vendor_name) as vendor_score
FROM v2_invoices inv
JOIN v2_purchase_orders pos ON
  similarity(inv.vendor_name, pos.vendor_name) > 0.85
  AND ABS(inv.amount - pos.total_amount) <= pos.total_amount * 0.10
  AND inv.invoice_date BETWEEN pos.created_at AND pos.created_at + INTERVAL '90 days'
ORDER BY vendor_score DESC;
```

#### C. Approval Workflow

Current workflow: received → needs_approval → approved → in_draw → paid

**Streamlined Workflow:**

| Confidence | Action |
|------------|--------|
| ≥95% + exact PO match | Auto-approve |
| 80-95% | Quick review (1-click confirm) |
| <80% | Full manual review |

**Quick Actions:**
- **Swap job** - Common correction, one dropdown
- **Change amount** - Direct edit with validation
- **Split invoice** - Already implemented
- **Batch approval** - Multi-select approve for high-confidence invoices

**Human-in-the-Loop Feedback:**
```javascript
// Record corrections for learning
async function recordCorrection(invoiceId, field, aiValue, userValue, entityId) {
  await recordFeedback({
    invoiceId,
    fieldName: field,
    aiValue,
    userValue,
    entityId,
    correctedBy: currentUser
  });

  // Apply to learning system
  if (field === 'vendor') {
    await recordLearning('vendor', aiValue, entityId, userValue);
    await recordVendorAlias(entityId, aiValue, 'correction');
  }
}
```

### 2.2 Key Metrics

**Cost Performance:**
| Metric | Calculation | Target |
|--------|-------------|--------|
| Cost Variance (CV) | Budgeted - Actual | ≤5% overrun |
| Budget Variance % | (Budget - Actual) / Budget × 100 | ≤5% |
| Completion % | billed_amount / budgeted_amount | — |

**Financial Health:**
| Metric | Calculation | Industry Avg |
|--------|-------------|--------------|
| Gross Profit Margin | (Revenue - Direct Costs) / Revenue | 19-22% |
| Net Profit Margin | Net Income / Revenue | 8-11% |
| Working Capital | Current Assets - Current Liabilities | — |

**Cash Flow:**
| Metric | Calculation |
|--------|-------------|
| Burn Rate | actual_spend / elapsed_time |
| Net Cash Flow | Cash Inflows - Cash Outflows |
| Days Cash on Hand | Cash Balance / Daily Burn Rate |

**Receivables:**
| Metric | Calculation |
|--------|-------------|
| A/R Turnover | Revenue / Average A/R |
| Days Payable Outstanding | A/P / Daily Purchases |
| Retainage Held | billed_amount × retainage_% |

### 2.3 Library Recommendations

#### Excel Generation: ExcelJS (already in use)

**Best practices:**
- Apply styles to cells BEFORE adding content (ExcelJS optimizes this pattern)
- Use WorkbookWriter for files >10MB or >10k rows
- Stream directly to response — never buffer entire file in memory

**Standard Report Pattern:**
```javascript
const ExcelJS = require('exceljs');

async function generateJobCostReport(jobId, response) {
  const workbook = new ExcelJS.Workbook();
  const sheet = workbook.addWorksheet('Job Cost Report');

  // Define columns with formatting
  sheet.columns = [
    { header: 'Cost Code', key: 'code', width: 15 },
    { header: 'Description', key: 'name', width: 30 },
    { header: 'Budget', key: 'budget', width: 15, style: { numFmt: '$#,##0.00' } },
    { header: 'Committed', key: 'committed', width: 15, style: { numFmt: '$#,##0.00' } },
    { header: 'Actual', key: 'actual', width: 15, style: { numFmt: '$#,##0.00' } },
    { header: 'Variance', key: 'variance', width: 15, style: { numFmt: '$#,##0.00' } }
  ];

  // Style header row BEFORE adding data
  sheet.getRow(1).fill = {
    type: 'pattern',
    pattern: 'solid',
    fgColor: { argb: 'FF4472C4' }
  };
  sheet.getRow(1).font = { bold: true, color: { argb: 'FFFFFFFF' } };

  // Add data rows
  const budgetData = await getBudgetLines(jobId);
  budgetData.forEach(item => sheet.addRow(item));

  // Stream to response
  response.setHeader('Content-Type', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet');
  response.setHeader('Content-Disposition', 'attachment; filename=job-cost-report.xlsx');
  await workbook.xlsx.write(response);
}
```

**Streaming for Large Datasets:**
```javascript
async function streamLargeReport(query, response) {
  const workbook = new ExcelJS.stream.xlsx.WorkbookWriter({
    stream: response,
    useStyles: true,
    useSharedStrings: false  // Faster if no formatting needed
  });

  const sheet = workbook.addWorksheet('Data');
  // ... add columns ...

  // Stream from database cursor
  const cursor = db.find(query).cursor();
  for await (const doc of cursor) {
    sheet.addRow(doc).commit();  // Flush row to stream
  }
  await workbook.commit();
}
```

*Source: [ExcelJS NPM](https://www.npmjs.com/package/exceljs)*

#### PDF Generation: pdfmake vs Puppeteer

| Aspect | pdfmake | Puppeteer |
|--------|---------|-----------|
| **Tables** | Excellent (spans, auto-sizing, header repeat) | Good (HTML tables) |
| **Charts** | Manual drawing | Via Chart.js/D3.js |
| **Performance (small)** | ~50ms per doc | 200-500ms startup |
| **Performance (large)** | Degrades >5MB | Better for large files |
| **Maintenance** | JSON declarative | HTML/CSS |
| **Best for** | Invoices, reports, forms | Complex layouts, existing HTML |

**Recommendation:** Use **pdfmake** for structured reports (tabular data, G702/G703), use **Puppeteer** only if rendering existing HTML pages.

**pdfmake Pattern for Professional Reports:**
```javascript
const pdfmake = require('pdfmake/build/pdfmake');
const pdfFonts = require('pdfmake/build/vfs_fonts');
pdfmake.vfs = pdfFonts.pdfMake.vfs;

function generateJobCostPDF(job, budgetLines) {
  const docDefinition = {
    pageSize: 'A4',
    pageMargins: [40, 60, 40, 60],

    header: (currentPage, pageCount) => ({
      text: `Job Cost Report - Page ${currentPage} of ${pageCount}`,
      alignment: 'right',
      fontSize: 10,
      margin: [40, 20, 40, 0]
    }),

    content: [
      { text: job.name, style: 'title' },
      { text: `Generated: ${new Date().toLocaleDateString()}`, style: 'subtitle' },

      {
        table: {
          headerRows: 1,
          widths: ['15%', '30%', '15%', '15%', '15%', '10%'],
          body: [
            [
              { text: 'Code', style: 'tableHeader' },
              { text: 'Description', style: 'tableHeader' },
              { text: 'Budget', style: 'tableHeader' },
              { text: 'Committed', style: 'tableHeader' },
              { text: 'Actual', style: 'tableHeader' },
              { text: 'Var %', style: 'tableHeader' }
            ],
            ...budgetLines.map(line => [
              line.code,
              line.name,
              { text: formatCurrency(line.budget), alignment: 'right' },
              { text: formatCurrency(line.committed), alignment: 'right' },
              { text: formatCurrency(line.actual), alignment: 'right' },
              {
                text: `${line.variancePercent}%`,
                alignment: 'center',
                color: line.variancePercent > 5 ? 'red' : 'green'
              }
            ])
          ]
        }
      }
    ],

    styles: {
      title: { fontSize: 24, bold: true, color: '#1F4E78' },
      subtitle: { fontSize: 12, color: '#666', margin: [0, 0, 0, 20] },
      tableHeader: { bold: true, fillColor: '#D9E1F2', color: '#1F4E78' }
    }
  };

  return pdfmake.createPdf(docDefinition);
}
```

### 2.4 Report Structure Recommendations

#### By Audience

**For Project Managers:**
- Focus: Progress, budget adherence, spend by cost code
- Structure: Current month + YTD + forecast to completion
- Key metrics: Budget variance %, % complete, remaining budget, burn rate
- Highlight: Overruns by cost code (color-coded), change order tracking
- Frequency: Weekly or bi-weekly during active phases

**For Owners/Principals:**
- Focus: Overall project profitability, cash implications, risk exposure
- Structure: Portfolio view summarizing all projects, then individual job summaries
- Key metrics: Gross margin %, committed costs, gross profit dollars
- Highlight: Projects at risk (flag overruns >10%), variance trends
- Frequency: Monthly with forecast updates

**For Accountants:**
- Focus: Accuracy, audit trail, financial statement impact
- Structure: Detailed cost code breakdown, reconciliation to general ledger
- Key metrics: Accrued expenses, unbilled receivables
- Frequency: Monthly for financial close, ad-hoc for audit support

#### Report Templates

**Job Cost Report:**
```
Header: Job Name, Report Date, Period
```
