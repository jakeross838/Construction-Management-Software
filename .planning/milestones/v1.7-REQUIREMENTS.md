# Requirements: Ross Built CMS v1.7

**Defined:** 2026-01-19
**Core Value:** Foolproof invoice -> approval -> draw -> budget pipeline with accurate data flow

## v1 Requirements

Requirements for v1.7 Data Integrity & AI Accuracy milestone.

### Budget Integrity

- [x] **BUD-INT-01**: Create `increment_committed_amount` RPC function that atomically updates budget committed amounts when PO approved
- [x] **BUD-INT-02**: Create `decrement_committed_amount` RPC function that atomically reverses committed amounts when PO voided
- [x] **BUD-INT-03**: Prevent budget line creation with zero budgeted_amount (require explicit budget before invoicing)
- [x] **BUD-INT-04**: Sync committed_amount correctly across all PO lifecycle events (create, approve, void, CO approval)

### Invoice Pipeline

- [x] **INV-INT-01**: Clean up allocations when invoice status transitions to denied/deleted (remove from PO line items, budget lines)
- [x] **INV-INT-02**: Wrap critical invoice operations in database transactions (approve, allocate, add-to-draw)
- [x] **INV-INT-03**: Recalculate billed_amount when allocations are modified after invoice added to draw
- [x] **INV-INT-04**: Validate that allocation sum equals invoice amount before allowing approval

### Draw Accuracy

- [x] **DRW-INT-01**: Always recalculate draw total from allocations on GET endpoint (don't trust stored total_amount)
- [x] **DRW-INT-02**: Include all budgeted cost codes in G703 even if no billings yet (show 0% progress)
- [x] **DRW-INT-03**: Validate draw allocations match source invoice allocations (detect drift)

### PO/CO Linking

- [x] **PO-INT-01**: Sync PO line item invoiced_amount bidirectionally when allocations change
- [x] **PO-INT-02**: Track CO invoiced_amount correctly when invoices with CO allocations are approved
- [x] **PO-INT-03**: Reverse committed_amount in budget when PO is voided (currently orphaned)
- [x] **PO-INT-04**: Prevent double-counting of CO billings (validate mutual exclusivity of manual vs allocated vs unlinked)

### AI Accuracy

- [x] **AI-INT-01**: Raise job matching confidence threshold from 0.5 to 0.7 minimum
- [x] **AI-INT-02**: Improve scanTextForKnownJobs to check more text patterns (ship-to, project, customer fields)
- [x] **AI-INT-03**: Add robust date validation (reject dates like 2024-05-34, use null instead)
- [x] **AI-INT-04**: Improve vendor name extraction from top of invoice (not confuse with customer/job)
