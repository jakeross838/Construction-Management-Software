## Milestone Summary

**Key Decisions:**

- `increment_committed_amount` raises exception if budget line missing (prevents committing to non-existent lines)
- `decrement_committed_amount` is no-op for missing budget lines (PO void succeeds gracefully)
- RPC failures logged but don't fail PO operations (graceful degradation)
- 0.01 tolerance for allocation sum validation (floating point rounding)
- Separate NO_ALLOCATIONS and ALLOCATION_MISMATCH errors for clearer UX
- Best-effort rollback pattern (manual state tracking since Supabase JS lacks transactions)
- Rollback in reverse order of completion

**Issues Resolved:**

- `increment_committed_amount` RPC function called but never created
- Budget lines created with $0 budgeted_amount when invoice allocated
- No allocation cleanup on invoice denial/deletion
- Draw totals stored but not always recalculated
- Job matching confidence threshold too low (50% → 70%)

- None
